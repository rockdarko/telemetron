# roles/garage

Deploys [Garage](https://garagehq.deuxfleurs.fr/) v2.3.0 -- an actively
maintained, AGPL-licensed S3-compatible object store -- on a single Docker
host. Garage is the backing store for Telemetron's Loki (log chunks),
Tempo (trace blocks), and Mimir (metric blocks + ruler + alertmanager state).
This role replaces the archived MinIO community edition.

## What this role does

1. Renders `/opt/telemetron/garage/garage.toml` from
   `templates/garage.toml.j2` with credentials pulled from
   `secrets.yml` (admin token and RPC secret).
2. Ensures two named Docker volumes exist: `telemetron_garage_meta`
   (Garage's lmdb metadata store) and `telemetron_garage_data`
   (S3 object blocks).
3. Starts the `telemetron-garage` container on the `telemetron`
   Docker bridge network, with a Docker `HEALTHCHECK` (binary-alive
   proxy: `/garage --version`) and `restart: unless-stopped`.
   Container ports are NOT published to the host by default
   (`garage_publish_host: false`).
4. **As a blocking final task**, runs a multi-step bootstrap sequence:
   - Polls Garage's Docker HEALTHCHECK via
     `community.docker.docker_container_info` until `State.Health.Status`
     reports `healthy`.
   - Gets the Garage node ID and assigns a single-node layout
     (`zone: local, capacity: 1G`) via `docker_container_exec`.
   - Applies the layout (`garage layout apply --version 1`).
     Layout assign/apply are gated with a defensive dual-check
     (`rc != 0 OR 'NO ROLE ASSIGNED' in stdout`) so re-runs skip
     them safely.
   - Checks for an existing S3 credentials host file
     (`{{ garage_s3_credentials_file }}`). If absent, creates a new
     Garage S3 key via `garage key create -n telemetron`, parses the
     JSON output, and persists the key ID and secret to the host file
     (mode 0600). On re-runs, loads credentials from the file instead
     of regenerating (per D-112).
   - Creates all five required buckets (`garage bucket create`), with
     idempotent handling of already-existing buckets.
   - Grants the S3 key read/write/owner permissions on each bucket
     (`garage bucket allow`).
   - Verifies all five buckets exist (`garage bucket info`).

(`garage key create`) and persisted to `{{ garage_s3_credentials_file }}`
(mode 0600). Subsequent runs load them from the host file. Operators
do not need to supply or manage S3 credentials.

## Secrets

Required keys in `inventory/<env>/group_vars/all/secrets.yml`:

| Key | Purpose |
|-----|---------|
| `garage_admin_token` | Bearer token for Garage admin API and Prometheus metrics scrape. Generate: `openssl rand -hex 32` |
| `garage_rpc_secret` | 32-byte hex secret for Garage inter-node RPC (single-node: required by Garage but not used for communication). Generate: `openssl rand -hex 32` |

Placeholders ship in `inventory/example-homelab/group_vars/all/secrets.yml.example`.

**S3 credentials are NOT in secrets.yml.** The bootstrap generates
them via `garage key create` on first run and persists them to
`{{ garage_s3_credentials_file }}` (mode 0600) per D-112. Per-backend
S3 key isolation is a deferred hardening milestone (D-111).

## Modes

Single mode only: monolithic single-node (`replication_factor = 1`).
Multi-node Garage deployment (replication across storage nodes) is a
future milestone and is not part of this role's variable surface.

| Volume | Type | Mount | Purpose |

## Healthcheck

Docker HEALTHCHECK uses a binary-alive proxy: `[CMD, /garage, --version]`.
This exits 0 if the Garage binary is present and executable, satisfying
the HEALTHCHECK without requiring an HTTP endpoint. The authoritative
readiness gate is the bootstrap sequence succeeding.

Verify with:

```bash
docker inspect telemetron-garage --format '{{.State.Health.Status}}'
# expects: healthy
```

The bucket-bootstrap subtask polls this same HEALTHCHECK status via
`community.docker.docker_container_info` before proceeding with layout
and key operations.

## Security model

- **Default: no host port publish.** Inter-component traffic stays on
  the `telemetron` Docker bridge. Operator access via SSH local-forward.
  RPC port (3901) is never published regardless of `garage_publish_host`.
- **Admin/RPC credentials from operator-supplied secrets.** Both
  `garage_admin_token` and `garage_rpc_secret` must be defined in
  `secrets.yml`; the role errors out on undefined vars. Generate with
  `openssl rand -hex 32`. Change the placeholders in `secrets.yml.example`.
- **S3 credentials auto-generated and persisted to host file with mode
  0600 (D-112).** The key ID and secret are generated inside the running
  container on first run and written to `{{ garage_s3_credentials_file }}`
  on the host. Only root/ansible user can read the file. Credentials
  never pass through `docker_container_exec` command arguments (they
  are only parsed from Garage's JSON output and written via Ansible copy).
- **Inter-component traffic on the `telemetron` Docker bridge only.**
  Loki, Tempo, and Mimir reach Garage at `http://garage:3900` over
  the bridge -- never via the host.
- **Single shared S3 API key (D-111 accepted risk).** Bootstrap creates
  one key with read/write/owner on all five buckets. Per-backend key
  isolation (separate key per Loki/Tempo/Mimir with bucket-scoped
  permissions) is a deferred hardening milestone.

## Idempotency

Per OPS-04: running the playbook twice in a row against an unchanged
inventory reports `changed=0` in the PLAY RECAP.

- **Layout assign/apply**: gated on a defensive dual-check
  (`rc != 0 OR 'NO ROLE ASSIGNED' in stdout`). On re-runs where the
  layout is already applied, the gate condition is false and both tasks
  are skipped. The `--version 1` argument to `layout apply` is safe
  because it is only ever called on first run.
- **Bucket create**: accepts both `rc=0` (clean create) and
  `rc != 0` with `'already exists'` in stderr via `failed_when`. Re-runs
  against existing buckets do not fail.
- **S3 key creation**: gated on the `garage_s3_credentials_file` host file
  stat check. If the file exists, `garage key create` is skipped and
  credentials are loaded from the file (D-112). Re-runs report `changed=0`.
- **Bucket allow**: idempotent by Garage's design (re-granting existing
  permissions is a no-op with `rc=0`).
- **Config change**: modifying `garage.toml.j2` variables notifies the
  `restart garage` handler, which runs `docker restart telemetron-garage`.
  The handler fires once per play even if multiple templates notify it.

Verify idempotency with:

```bash
ansible-playbook -i inventory/example-homelab \
                 playbooks/deploy_docker.yml --tags garage
# ...first run: changed=N
ansible-playbook -i inventory/example-homelab \
                 playbooks/deploy_docker.yml --tags garage
# ...second run: changed=0
```

## Port-acceptance gates

This role passes all gates documented in `roles/README.md`:

- **Grep gates:** Zero INSPQ/French-language references in `roles/garage/`.
  Zero non-ASCII characters in `roles/garage/`.
- **Image-pin gate:** `dxflrs/garage:v2.3.0` -- explicit release tag, not
  floating.
- **Secrets-discipline gate:** `garage_admin_token` and `garage_rpc_secret`
  have matching CHANGE_ME placeholders in `secrets.yml.example`. S3
  credentials are not in secrets.yml (auto-generated per D-112).
- **Idempotency gate:** second run reports `changed=0` (layout and key
  creation gated; bucket operations idempotent).
- **Healthcheck + restart-policy gate:** `docker inspect telemetron-garage`
  returns `healthy` and `unless-stopped`.
- **README gate (OPS-03):** this file.
- **Gate 7 labels:** container stamps `org.telemetron.service: telemetron`
  and `org.telemetron.job: garage`.
- **Gate 8 parent-dir mounts:** `garage_config_dir` is bind-mounted as
  the parent directory `/etc/garage`, not as a single-file mount. Garage
  reads `garage.toml` from within that directory.

## Data migration note

For leviathan (UAT host) and fresh deployments, no data migration is
required -- Garage starts with empty volumes. Production operators with
existing MinIO data who are migrating to Garage can use
[rclone](https://rclone.org/) to copy objects between the MinIO and
Garage S3 endpoints before switching the role. Switching the role
without migrating will result in empty backends (Loki, Tempo, and Mimir
will start fresh). Migrating existing data before switching is outside
the scope of this role but is documented in Telemetron's REQUIREMENTS.md
out-of-scope table.

## Bring your own bucket names

Override `telemetron_garage_buckets` in
`inventory/<env>/group_vars/all/storage.yml` to rename or add buckets.
Renaming a bucket here MUST be paired with renaming in the consuming
backend role's S3 config (roles/loki, roles/tempo, roles/mimir).
