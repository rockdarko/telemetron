## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fluentbit enrich.lua bind-mount verify check used individual file path**

- **Found during:** Task 7 (leviathan run 1, fluentbit-verify step)
- **Issue:** `roles/fluentbit/tasks/verify.yml` Task 4 ("Verify enrich.lua is bind-mounted") used `selectattr('Destination', 'equalto', fluentbit_enrich_lua_path)` where `fluentbit_enrich_lua_path = /fluent-bit/etc/enrich.lua`. Phase 04-02 converted all single-file bind mounts to parent-directory mounts (Gate 8 / moby/moby#6011). The container mount Destination is now `/fluent-bit/etc` (the directory), not the individual file path. The check always failed because no mount had that exact Destination.
- **Fix:** Added `fluentbit_config_container_dir: "/fluent-bit/etc"` to `roles/fluentbit/defaults/main.yml`. Changed `selectattr` filter in `verify.yml` from `fluentbit_enrich_lua_path` to `fluentbit_config_container_dir`. Updated inline comment to document the Phase 04-02 Gate 8 context.
- **Files modified:** `roles/fluentbit/tasks/verify.yml`, `roles/fluentbit/defaults/main.yml`
- **Commit:** b220114

**2. [Rule 2 - Missing Security] Added **/secrets.yml to .gitignore**

- **Found during:** Task 2 (creating secrets.yml.example, noticing secrets.yml was not gitignored)
- **Issue:** `.gitignore` had `**/vault.yml` but not `**/secrets.yml`. After renaming `vault.yml.example` -> `secrets.yml.example`, operators copying this to `secrets.yml` would have their real secrets unprotected from accidental `git add`.
- **Fix:** Added `**/secrets.yml` to `.gitignore` alongside `**/vault.yml`.
- **Files modified:** `.gitignore`
- **Commit:** 4ba604e
