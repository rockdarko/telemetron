    Create the two task files that deploy and bootstrap the Garage container.

    tasks/main.yml — follows MinIO's task ordering exactly (per PATTERNS.md):
    1. Ensure Garage config directory exists on host (ansible.builtin.file, path {{ garage_config_dir }}, mode 0755, tags garage/garage-config)
    2. Render Garage TOML config (ansible.builtin.template, src garage.toml.j2, dest {{ garage_config_dir }}/garage.toml, mode 0600, notify restart garage, tags garage/garage-config)
    3. Ensure Garage metadata volume exists (community.docker.docker_volume, name {{ garage_meta_volume }}, tags garage)
    4. Ensure Garage data volume exists (community.docker.docker_volume, name {{ garage_data_volume }}, tags garage)
    5. Pull Garage image (community.docker.docker_image, name {{ garage_image }}:{{ garage_image_tag }}, source pull, force_source false, tags garage)
    6. Run Garage server container (community.docker.docker_container):
       - name: {{ garage_container_name }}
       - image: {{ garage_image }}:{{ garage_image_tag }}
       - state: started, recreate: false
       - restart_policy: {{ garage_restart_policy }}
       - memory: {{ garage_memory_limit }}
       - NO env_file (Garage reads TOML, not env). Instead, pass env dict with GARAGE_CONFIG_FILE: "/etc/garage.toml"
       - NO command block (image CMD is /garage server)
       - networks: [{ name: {{ garage_network }}, aliases: [{{ garage_container_name }}, garage] }]
       - labels: { org.telemetron.service: telemetron, org.telemetron.job: garage } (Gate 7)
       - published_ports: conditional triple using garage_publish_host sentinel — publish garage_api_port and garage_admin_port (RPC port 3901 is internal-only, never published)
       - mounts: THREE entries — volume mount for garage_meta_volume at garage_meta_path, volume mount for garage_data_volume at garage_data_path, bind mount for {{ garage_config_dir }} at /etc/garage (parent directory, Gate 8) with read_only: true
       - healthcheck: garage_healthcheck_test/interval/timeout/retries/start_period
       - tags garage/garage-container
    7. Include bootstrap.yml as blocking final task (D-08), tags garage/garage-bootstrap

    tasks/bootstrap.yml — multi-step docker_container_exec sequence (per RESEARCH Pattern 2):
    Step 1: Wait for Garage HEALTHCHECK healthy (community.docker.docker_container_info poll, same until: guard as MinIO, retries/delay from defaults, changed_when: false)
    Step 2: Get Garage node ID (docker_container_exec, command /garage node id --quiet, register garage_node_id_raw, changed_when: false)
    Step 3: Set garage_node_id fact (set_fact extracting hex ID: {{ garage_node_id_raw.stdout.split('@')[0] }})
    Step 4: Check Garage layout status (docker_container_exec, command /garage layout show, register garage_layout_show, changed_when: false)
    Step 5: Assign Garage layout (docker_container_exec, command /garage layout assign -z {{ garage_layout_zone }} -c {{ garage_layout_capacity }} {{ garage_node_id }}, changed_when: true, when: "'NO ROLE ASSIGNED' in garage_layout_show.stdout")
    Step 6: Apply Garage layout (docker_container_exec, command /garage layout apply --version 1, changed_when: true, when: "'NO ROLE ASSIGNED' in garage_layout_show.stdout")
    Step 7: Import Garage S3 key (docker_container_exec, command /garage key import --yes -n {{ garage_s3_key_name }} {{ garage_s3_access_key_id }} {{ garage_s3_secret_key }}, changed_when: false). Note: key import is idempotent per RESEARCH — re-importing same key-id is safe.
    Step 8: Create Garage buckets (docker_container_exec loop over garage_buckets, command /garage bucket create {{ item }}, changed_when: false, register garage_bucket_create, failed_when: rc != 0 AND 'already exists' not in stderr | default(''))
    Step 9: Allow S3 key on each bucket (docker_container_exec loop over garage_buckets, command /garage bucket allow --read --write --owner {{ item }} --key {{ garage_s3_key_name }}, changed_when: false)
    Step 10: Verify all buckets exist (docker_container_exec loop over garage_buckets, command /garage bucket info {{ item }}, changed_when: false, register garage_bucket_verify, failed_when: rc != 0)

    All steps tagged with garage and garage-bootstrap. All non-layout steps use changed_when: false. Layout steps are gated with when: to skip on re-runs.

    IMPORTANT: The GARAGE_CONFIG_FILE env must point to /etc/garage/garage.toml (inside the parent directory bind mount), NOT /etc/garage.toml. The bind mount maps the host directory {{ garage_config_dir }} to the container path /etc/garage. The config file inside is garage.toml, so the full container path is /etc/garage/garage.toml.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ansible controller -> Garage container | Credentials (admin_token, rpc_secret, S3 keys) passed via docker_container_exec args and rendered into garage.toml |
| telemetron bridge -> Garage admin API | Admin API on 0.0.0.0:3903 is reachable by any container on the bridge (Prometheus, and potentially others) |
| telemetron bridge -> Garage S3 API | S3 API on [::]:3900 accepts any SigV4-signed request with valid credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure | garage.toml (rpc_secret, admin_token) | mitigate | Template rendered with mode 0600; bind-mounted read-only into container; garage_config_dir host directory mode 0755 (standard for role config dirs); values sourced from secrets.yml which is gitignored |
| T-08-02 | Information Disclosure | docker_container_exec args | accept | Key import args (access_key_id, secret_key) visible in process list during execution; same exposure class as MinIO mc bootstrap (D-09); bounded to bootstrap run window (<5s typically); documented in README Security model section |
| T-08-03 | Spoofing | Garage admin API (0.0.0.0:3903) | mitigate | Admin API requires Bearer token (garage_admin_token) for all operations; garage_publish_host defaults to false so admin port is not exposed on host; traffic stays on Docker bridge network |
| T-08-04 | Elevation of Privilege | S3 API single shared key (D-111) | accept | Single key has read/write/owner on all 5 buckets; per-backend key isolation deferred to hardening milestone; documented in README as known limitation |
| T-08-05 | Tampering | rpc_secret static value | mitigate | rpc_secret is a 32-byte hex string from secrets.yml (operator generates via openssl rand -hex 32); unique per deployment; CHANGE_ME placeholder in secrets.yml.example forces operator action |
| T-08-SC | Tampering | Docker image pull | mitigate | dxflrs/garage:v2.3.0 verified by direct pull and local inspect (sha256:866bd13ed2038ba7e7190e840482bc27234c4afaf77be8cfa439ae088c1e4690); no npm/pip installs; image pin is explicit tag not :latest |
</threat_model>
