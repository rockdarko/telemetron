## Overview

v1.1.0 closes the four M1 backlog items left at v1.0.0 ship and migrates Telemetron's S3-compatible object store off the archived `minio/minio` community image onto `dxflrs/garage:v2.3.0`. The migration spans backend retargeting (Loki/Tempo/Mimir all writing through Garage's `:3900` API), full removal of the MinIO role, three config-template regression fixes (Mimir retention, Tempo compaction window, Fluent Bit Lua timestamp fallback), and a Loki label reconciliation that aligns Fluent-Bit-originated and OTel-Collector-originated logs under a single `service_name` query surface. v1.1.0 is the first Telemetron milestone with full live-UAT validation on the homelab target (leviathan) — three Phase 8 bootstrap regressions only surfaced during the live deploy, confirming that ansible deploy phases require a real runtime gate beyond the static verifier.

### Issues Surfaced + Fixed During Live UAT

Three Phase 8 garage-bootstrap regressions only surfaced during the leviathan cutover deploy. The Phase 8 verifier was static-only and signed off PASS; no live deploy had been attempted before the Phase 9 follow-on UAT. All three were fixed atomically inline:

| Commit | Fix | Root cause |
|---|---|---|
| `4839bcb` | Drop invalid `-n` flag from `garage key create` | Garage v2.3.0 takes the key name positionally; `-n` doesn't exist. Authored against assumed CLI shape. |
| `0b73941` | Layout check uses `garage status` not `garage layout show` | `NO ROLE ASSIGNED` string appears in per-node `garage status` output, not in `garage layout show`. Defensive when-guard never fired. |
| `8c8807d` | Parse credentials host-file via `regex_search('(?m)^key_id=(.+)$', '\\1')` | `(content \| b64decode).split('\n')` left `\n` as literal 2-char string in YAML-single-quoted Jinja; `match('^key_id=')` regex didn't anchor on the unsplit blob. |

### Lessons Learned

- **The `human_needed` verifier verdict is load-bearing for ansible deploy phases.** Static verification cannot catch CLI-arg mismatches, runtime Jinja parsing quirks, or defensive guard logic that fails to trigger on actual command output. The `project_leviathan_uat_host.md` operator memory ("run live-Docker tests yourself, don't punt to human_needed") was empirically validated by three real regressions caught.
- **Worktree HEAD-assertion in gsd-executor prompts is fragile.** Plan 09-01's executor worktree forked from `71d6d55` (milestone start) instead of the intended `77a9f26` (EXPECTED_BASE). The `git reset --hard $EXPECTED_BASE` HEAD-assertion block did not fire as designed. Orchestrator recovered transparently via `git rebase 77a9f26` on the worktree branch — clean rebase, no conflicts, because the agent's edits targeted disjoint lines from intervening phase 7/8 work. Worth a prompt-level fix note for the gsd-executor.
- **D-128 clean-break label transition was the right call.** Operators on the upgrade path query historical pre-migration data with `{service="..."}` and new data with `{service_name="..."}`; no relabeling alias period, no rule maintenance. The `## Upgrade notes` quickstart subsection makes this discoverable.
