## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → Ansible | Operator runs `ansible-playbook` with `--ask-vault-pass` |
| Ansible → Docker daemon | `become: true` tasks invoke `docker` CLI as root |
| Docker volume `_data/` ↔ tarball | Root-owned host path read by tar (backup) / wiped + re-written (restore) |
| Restore source tarball → volume `_data/` | Wipe + untar replaces existing TSDB contents irreversibly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03-01 | Tampering | Stale lock-file replay attack | mitigate | PP-1 `ansible.builtin.file: state: absent` on `_data/lock` unconditionally after untar removes any attacker-injected lock file alongside the legitimate stale one. The container is stopped at this point — no Prometheus process holds the lock. |
| T-13-03-02 | Tampering | Tarball corruption | mitigate | `tar --zstd -tf` integrity check BEFORE wipe. Same as Garage restore. |
| T-13-03-03 | Denial of service | Restore wipes TSDB on misfire | mitigate | Role-level `backup_restore_confirm=true` fail-fast gate + `tar --zstd -tf` integrity gate. Two layers before any destructive operation. |
| T-13-03-04 | Information disclosure | TSDB time-series values in tarball | accept | Prometheus metric values are observability data, not user secrets. Mode 0600 tarball + 0700 dest dir is the v1.3.0 default. Encryption at rest deferred. |
| T-13-03-05 | Information disclosure | WARN msg echoing data | mitigate | WARN names `{{ prometheus_data_volume }}` only — no `tar tf` listing in WARN output. |
