# Phase 13: Per-Role Backup & Restore Tasks - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 13 ships eight new Ansible task files — `tasks/backup.yml` and `tasks/restore.yml` for each of the four stateful Telemetron roles (`garage`, `prometheus`, `grafana`, `alertmanager`) — implementing the cold-quiesce backup/restore model locked in PROJECT.md. Each backup task quiesces its container, snapshots the Docker volume(s) (plus the Garage `s3-credentials` host file), restarts the container, and runs verify. Each restore task gates on `backup_restore_confirm=true`, integrity-checks the source tarball, wipes the `_data/` directory, untars, restarts, and runs verify. The orchestrators (`backup_docker.yml` / `restore_docker.yml`) and the leviathan round-trip HUMAN-UAT live in Phase 14; the doc cascade + Gate 11 live in Phase 15.

Phase 13 covers 9 of the 18 v1.3.0 requirements: BACKUP-V13-01..04, RESTORE-V13-01..04, OPS-V13-04.

</domain>

<decisions>
## Implementation Decisions

### Garage tarball shape (D-176)
- **D-176:** Single tarball per Garage backup. Filename: `garage-<timestamp>.tar.zst` at `/opt/telemetron/backups/garage/`. Three top-level entries inside: `meta/` (from `telemetron_garage_meta` volume), `data/` (from `telemetron_garage_data` volume), and `s3-credentials` (from the `{{ garage_s3_credentials_file }}` host bind-mount). Symmetric with the other 3 stateful roles (one tarball per role); restore is a single untar; latest-discovery is uniform across all roles. Two-tarball alternative (meta + data split) rejected — asymmetry adds ordering surface for restore and a second sort regex for latest-discovery without recovering a real failure mode (any single-volume corruption case is already covered by the operator keeping multiple dated backups).

### Stop-timeout per role (D-177)
- **D-177:** Shared default `backup_stop_timeout: 60` lives in `inventory/example-homelab/group_vars/all/backup.yml` (new file). Per-role override `<role>_backup_stop_timeout` in each role's `defaults/main.yml` defaulting from the shared var: `garage_backup_stop_timeout: "{{ backup_stop_timeout }}"`, same shape for prometheus/grafana/alertmanager. Each `tasks/backup.yml` and `tasks/restore.yml` issues `docker stop -t {{ <role>_backup_stop_timeout }} {{ <role>_container_name }}` to give Prometheus TSDB checkpoint and Garage LMDB clean-close ~6× the Docker default (10s) before SIGKILL. Operators can tune up (giant TSDB) or down without editing role code. Trust-default-10s rejected — SIGKILL mid-checkpoint reintroduces the PP-1 lock-file class of regression.

### Verify pattern (D-178)
- **D-178:** Each `tasks/backup.yml` and `tasks/restore.yml` calls `include_tasks: verify.yml` after the container restart, placed inside the `block`/`rescue`/`always` block's `always:` section so the restart + verify fires even on tar failure. Three of the four stateful roles already ship a `tasks/verify.yml` (prometheus, grafana, alertmanager) — re-used as-is, single source of truth for "this role is healthy." Garage diverges: it has NO `tasks/verify.yml` (verification is inline in `tasks/main.yml` + `tasks/bootstrap.yml`), so its `tasks/backup.yml` + `tasks/restore.yml` use an inline `community.docker.docker_container_info` poll until `State.Health.Status == healthy` (matches the Phase 4/5 `docker_container_exec` pattern that closed the auto_remove race class). Inline minimal probe alternative rejected for the 3 verify-bearing roles — it would diverge from the deploy-time correctness contract for no upside.

### Timestamp format + latest-discovery (D-179)
- **D-179:** ISO 8601 basic UTC: `YYYYMMDDTHHMMSSZ` (e.g., `20260603T143012Z`). Generated by `ansible.builtin.command: date -u +%Y%m%dT%H%M%SZ` registered as `backup_timestamp.stdout`. Tarball filename pattern: `<role>-<timestamp>.tar.zst`. Latest-discovery (Phase 14 orchestrator + restore default) uses `find /opt/telemetron/backups/<role>/ -name '<role>-*.tar.zst' -printf '%f\n' | sort -r | head -1` — lexicographic sort is chronological because the format is monotonic. Format is uniform across all 4 stateful roles; a single `*.tar.zst` glob is sufficient. STATE.md's `YYYYMMDD-HHMMSS` example is superseded by this lock — STATE.md will catch up on phase transition.

### Carrying forward from v1.0–v1.2 (no re-discussion)
- **Cold-quiesce model + `docker stop` (not `state: stopped`):** Locked in PROJECT.md after research surfaced XP-1 (community.docker `state: stopped` strips volume/mount specs). Every backup/restore task uses `ansible.builtin.command: docker stop` + `community.docker.docker_container_info` poll.
- **`block` / `rescue` / `always` container-restart guarantee:** Every backup task wraps the stop→tar sequence so the container restarts even on tar failure. Restore task wraps stop→wipe→untar→start the same way.
- **`backup_restore_confirm=true` gate at both orchestrator AND role-task level:** Mirrors v1.2.0 D-159 `telemetron_purge_data=true` safety contract.
- **Garage `s3-credentials` IS in the backup:** Without it, a post-restore `deploy_docker.yml` regenerates a new S3 key (hits the D-146 self-healing branch); Loki/Tempo/Mimir would lose their reference until redeploy. Bundling it in the Garage tarball avoids this entirely.
- **Prometheus `/prometheus/lock` deleted after untar, before `docker start`:** PP-1 — the lock file is PID-based and the restored tarball carries the stale lock.
- **`zstd` ensure-present pre-task in every backup/restore task:** Not pre-installed on Ubuntu 22 / Debian 12 / RHEL 9. `ansible.builtin.package: name: zstd state: present` (become: true). Idempotent.
- **Destination + permissions:** `/opt/telemetron/backups/<role>/` dir mode `0700`, tarballs mode `0600`. Directory created by the per-role backup task (lazy, idempotent) — no orchestrator-side bootstrap.
- **Cross-cutting tags:** Each task carries `tags: [<role>, backup]` (or `restore`), so `--tags backup` / `--tags restore` are valid cross-cutting commands AND `--tags <role>` partial runs work uniformly.

### Claude's Discretion (left to planner with safe defaults)
- **Pre-flight disk-space check:** Research recommended `backup_space_factor: 1.5` (require 1.5× volume size free). Planner decides whether to implement as a hard fail, soft warn, or skip. Default if planner is silent: skip — Telemetron has no precedent for hidden capacity knobs, and `tar`'s own ENOSPC failure is loud enough.
- **Alertmanager empty `data/` directory guard:** STACK.md open question 2. Planner picks the guard pattern (stat-then-skip-with-debug vs tar-empty-dir vs sentinel file) — `stat` check + conditional tar with `creates:`-style guard is the obvious default. Restore must handle the empty-state case symmetrically.
- **Sub-order within Phase 13:** Garage first (most complex: two volumes + config dir + bootstrap interaction), then Prometheus → Grafana → Alertmanager, per research recommendation. Plans can be written in parallel since the 8 task files don't share files.
- **STATE.md timestamp example update:** STATE.md line ~103 shows `YYYYMMDD-HHMMSS`; this CONTEXT.md locks `YYYYMMDDTHHMMSSZ`. The `/gsd:transition` between Phase 13 and Phase 14 should reconcile this; planner doesn't need to touch STATE.md itself.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`tasks/verify.yml`** (prometheus, grafana, alertmanager): Already battle-tested via deploy-time + Phase 4/5 gap-closure UAT. Phase 13 calls them post-restart inside the `always:` block of every backup + restore task. Garage has none — uses inline `docker_container_info` healthy poll instead.
- **`community.docker.docker_container_info` polling pattern** (from Phase 4/5 gap-closure): The canonical "wait until container is healthy" recipe that replaced auto_remove + detach races. Use the same `until: ... is succeeded` + `retries:` + `delay:` shape.
- **`tasks/uninstall.yml` header structure** (all 4 stateful roles): Phase 13 backup tasks should adopt the same docstring-style header explaining what's preserved vs what's snapshotted, plus the D-179 timestamp format note inline.
- **Existing `defaults/main.yml` shared-var pattern**: New `<role>_backup_stop_timeout` variables default-from `backup_stop_timeout` (`group_vars/all/backup.yml`) — same shape as `garage_container_name: telemetron-garage` defaulting from `telemetron_*` knobs.

### Established Patterns
- **`become: true` + `ansible.builtin.command: tar`**: Existing pattern for host-side root operations on Docker volume paths. No need to invent helper containers.
- **D-159 WARN format** (v1.2.0): `WARNING: irreversible -- <role> <action>: <targets>` — the restore-side debug task uses the `restore` action variant. Backup tasks do NOT emit this WARN (backup is not destructive).
- **`block` / `rescue` / `always`** (precedent: none in current `tasks/` — this is a new pattern Phase 13 introduces). Adoption shape locked: stop + tar in `block:`, container restart + verify in `always:`, no `rescue:` body beyond a debug WARN noting the failure (the `always:` clause is the operational guarantee).
- **Per-role tagging convention** (v1.2.0): `tags: [<role>, <action>]` — Phase 13 extends with `tags: [<role>, backup]` and `tags: [<role>, restore]`. `--tags backup` / `--tags restore` cross-cutting commands inherit from this.
- **No `community.general.archive`**: All tar operations go through `ansible.builtin.command: tar --zstd` directly — community.general is not in Telemetron's collection footprint and adds nothing zstd-compatible.

### Integration Points
- **Phase 14 orchestrators** (`playbooks/backup_docker.yml` + `restore_docker.yml`): Call `include_role: name=<role> tasks_from=backup` (or `tasks_from=restore`). Phase 13 must produce the right file paths.
- **`backup_restore_confirm=true` gate** lives in both the orchestrator AND each per-role `tasks/restore.yml`. A standalone `include_role: tasks_from=restore` from a custom operator playbook must also enforce the gate (REQUIREMENTS.md OPS-V13-01).
- **Phase 15 doc cascade** (`docs/quickstart.md`, per-role README `## Backup` H2): References the file paths and tag conventions Phase 13 ships. No coupling beyond filenames.

</code_context>

<specifics>
## Specific Ideas

- **New variables file:** `inventory/example-homelab/group_vars/all/backup.yml` (or merged into an existing all-scope file — planner's call). Holds `backup_dest_root: /opt/telemetron/backups`, `backup_stop_timeout: 60`, `backup_continue_on_failure: false`, `backup_restore_confirm: false`, `backup_restore_from: ""`. Per-role defaults pull from these.
- **Garage backup tarball internal layout (D-176):** Three top-level entries. The `meta/` entry is the contents of the `_data/` directory of `telemetron_garage_meta`. The `data/` entry is from `telemetron_garage_data`. The `s3-credentials` entry is the file from `{{ garage_s3_credentials_file }}`. Restore unpacks all three into their respective destinations.
- **Restore wipe pattern:** `ansible.builtin.find` + `ansible.builtin.file: state=absent` loop, OR `ansible.builtin.command: find {{ path }} -mindepth 1 -delete` (research preferred this for speed and idempotency). Planner picks one; both work. Avoids `docker_volume state=absent` per research §3.
- **Prometheus `/prometheus/lock` deletion is unconditional after untar:** `ansible.builtin.file: path={{ prometheus_data_path }}/lock state=absent` — no `ignore_errors` needed; `state: absent` is already idempotent.

</specifics>

- **Backup tarball checksum sidecar (`*.sha256`)** — FEATURES.md "deferred to v1.3.x or later." Phase 14 `tar tf` integrity check covers the same surface for v1.3.0.

- **`<role>-latest` symlink for each role** — Deferred. `find | sort -r | head -1` discovery is the v1.3.0 contract.
- **`backup_before_restore` auto-snapshot** — Deferred per FEATURES.md.
- **Off-host backup destination knobs** — BACKUP-V14-01/02; operator wraps Telemetron's local output.
