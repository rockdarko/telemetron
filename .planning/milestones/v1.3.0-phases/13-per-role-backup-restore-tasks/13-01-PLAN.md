## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → inventory | Operator-controlled `secrets.yml` + group_vars are loaded by Ansible at play time |
| inventory → role tasks | Variables propagate via Jinja from group_vars/all → role defaults → tasks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01-01 | Tampering | inventory/example-homelab/group_vars/all/backup.yml | accept | File is operator-managed and not vault-encrypted (no secrets — pure operational knobs). Standard Telemetron pattern: secrets in `secrets.yml`, operational vars in plain group_vars files. Mode 0644 is fine. |
| T-13-01-02 | Information disclosure | backup_dest_root default value | mitigate | Default `/opt/telemetron/backups/` is a path, not a secret; per-role subdirs created at mode 0700 by Task 13-02..13-05 (XP-4 mitigation). The DEFAULT value alone leaks nothing. |
| T-13-01-03 | Denial of service | backup_stop_timeout misconfiguration | accept | Operator-set 0 or negative value would cause `docker stop -t 0` (immediate SIGKILL) reintroducing PP-1/GP-1 risk. This is an operator footgun; default 60 is defensive. Phase 15 docs document the trade-off. No code-level guard. |
| T-13-01-04 | Elevation of privilege | Variable injection via group_vars | accept | Ansible interprets group_vars as data only; no `!!python` constructs or templated bash. Standard Telemetron threat surface; no per-plan novel exposure. |
| T-13-01-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan. The `zstd` ensure-present task is in plans 13-02..13-05 (each per-role task file). No legitimacy audit needed for this plan. |
</threat_model>
