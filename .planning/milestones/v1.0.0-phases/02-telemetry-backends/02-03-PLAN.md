This plan mirrors the canonical `roles/minio/` template AND the Phase-2 precedents established by Plans 02-01 (Loki) and 02-02 (Tempo). The Mimir-specific work:

1. **D-26 multitenancy disabled** — `multitenancy_enabled: false` (single-tenant `anonymous`); producers in Phase 3 (Prometheus `remote_write`) need no tenant header.
2. **D-28 gRPC port pin** — explicit `server.grpc_listen_port: 9097` (Loki 9095, Tempo 9096, Mimir 9097 — all three pinned to avoid the single-host clash).
3. **D-35 / BACK-04 retention** — `compactor.blocks_retention_period: 30d` (matching `telemetron_default_metric_retention`).

6. **D-39 S3 endpoint format** — `endpoint: minio:9000` (no scheme — same as Tempo, different from Loki); `insecure: true`. Mimir uses `force_path_style` in `common.storage.s3` — RESEARCH Finding 3 + Open Question #2 documents this; the rendered config sets `insecure: true` and relies on Mimir's default path-style behavior for MinIO (Mimir's S3 client auto-detects path-style for non-AWS endpoints; explicit `force_path_style` is supported but the key name varies by Mimir version; see Task 1's template implementation for the resolution).

    ```yaml
    ---
    # roles/mimir/defaults/main.yml
    # Mimir role tunables. Override per-environment in
    # inventory/<env>/group_vars/all/mimir.yml.
    #
    # Mimir 3.0.6 monolithic mode (-target=all). Storage backend: MinIO S3
    # with THREE DISTINCT BUCKETS -- Mimir refuses to start sharing
    # prefixes across blocks_storage / ruler_storage / alertmanager_storage
    # (PITFALLS.md Pitfall G + BACK-04).

    # --- Image pin (OPS-01) ---
    # Mimir 3.0.6 (2026-04-20) -- v3.0 line is current stable.
    # See: https://github.com/grafana/mimir/releases/tag/mimir-3.0.6
    mimir_image: grafana/mimir
    mimir_image_tag: "3.0.6"

    # --- Container identity ---
    # DNS name on the telemetron network. Phase 3 Prometheus remote_writes
    # to http://{{ mimir_container_name }}:9009/api/v1/push.
    mimir_container_name: mimir

    # --- Host port publishing (D-30) ---
    # Default: zero host publish. Operator access via SSH local-forward:
    #   ssh -L 9009:localhost:9009 <host>
    mimir_publish_host: "{{ mimir_publish_host | default(false) }}"

    # --- Port matrix (D-28, D-31) ---
    # HTTP API on :9009 (metrics push, /ready, /metrics, /api/v1/*).
    # gRPC on :9097 (D-28 explicit -- default 9095 clashes with Loki;
    # :9096 is taken by Tempo).
    mimir_http_port: 9009
    mimir_grpc_port: 9097

    # --- Storage layout (D-16, D-17, D-18, RESEARCH Finding 7) ---
    # One named Docker volume covers tsdb/, tsdb-sync/, compactor/,
    # alertmanager/, ruler/rules at the /data container root.
    mimir_data_volume: "{{ telemetron_volume_prefix | default('telemetron') }}_mimir_data"
    mimir_data_path: /data

    # Host-side config directory (D-18 flat layout).
    mimir_config_dir: "{{ telemetron_config_root | default('/opt/telemetron') }}/mimir"

    # --- S3 backend (D-39, RESEARCH Finding 3) ---
    # NOTE: Mimir's common.storage.s3.endpoint format omits the http://
    # prefix; insecure: true signals plain HTTP. Matches Tempo's convention
    # and differs from Loki's. See RESEARCH Open Question #2 -- the safe
    # answer is `minio:9000` no scheme.
    mimir_s3_endpoint: "minio:9000"
    mimir_s3_region: us-east-1
    mimir_s3_insecure: true

    # --- Three distinct buckets (BACK-04, Pitfall G, RESEARCH Finding 3) ---
    # Mimir refuses to start with shared bucket+prefix across these three
    # storage stores. The Phase 1 minio role bootstrapped all three buckets
    # already; this role just references them.
    mimir_blocks_bucket: mimir-blocks
    mimir_ruler_bucket: mimir-ruler
    mimir_alerts_bucket: mimir-alerts

    # --- Retention (D-35, BACK-04) ---
    # Compactor-driven block retention. Default 30d matches
    # telemetron_default_metric_retention. Override in inventory/mimir.yml.
    mimir_compactor_blocks_retention_period: "{{ telemetron_default_metric_retention | default('30d') }}"

    # --- Monolithic tuning (D-36, PITFALLS Pitfall 11 + Pitfall 3) ---
    # All five knobs explicit and inline-commented in the template.
    mimir_max_global_series_per_user: 500000      # Pitfall 3 homelab limit
    mimir_max_global_series_per_metric: 100000    # Pitfall 3 homelab limit
    mimir_query_store_after: 12h                  # Pitfall 11 -- longer than block-lands window
    mimir_bucket_store_sync_interval: 5m          # Pitfall 11 -- monolithic single-host
    mimir_compactor_cleanup_interval: 5m          # Pitfall 11 -- monolithic single-host

    # --- OOO time window (Claude's Discretion per D-39) ---
    # INSPQ ran with 30m; sensible homelab default. Protects against data
    # loss on restart when remote_write has buffered samples.
    mimir_ooo_time_window: 30m

    # --- Multitenancy (D-26) ---
    # Single-tenant `anonymous`. Phase 3 Prometheus does not send
    # X-Scope-OrgID header. Flipping this to true in a future hardening
    # phase requires updating every Phase-3 producer's tenant config.
    mimir_multitenancy_enabled: false

    # --- Healthcheck approach (RESEARCH Finding 6, PITFALLS Pitfall B) ---
    # Mimir 3.0.6 is distroless and has NO native health binary as of
    # research (issue #9034 closed unresolved). Same pattern as Tempo:
    # set tempo_healthcheck_test (renamed mimir_healthcheck_test here) to
    # a binary-alive proxy by default; the executor MAY override after
    # probing the image at execute time.
    #
    # When mimir_healthcheck_enabled is true: container HEALTHCHECK uses
    # mimir_healthcheck_test (CMD form). verify.yml polls State.Health.Status.
    # When false: HEALTHCHECK omitted; verify.yml polls State.Running plus
    # an in-network curl to /ready.
    mimir_healthcheck_enabled: true
    mimir_healthcheck_test: ["CMD", "/bin/mimir", "-version"]
    mimir_healthcheck_interval: 15s
    mimir_healthcheck_timeout: 5s
    mimir_healthcheck_retries: 5
    mimir_healthcheck_start_period: 60s

    # --- Verify pre-poll (D-10a) ---
    # 90s total budget. Mimir cold-start is moderate -- TSDB initialization
    # plus S3 bucket sync.
    mimir_health_retries: 45
    mimir_health_delay: 2

    # --- Restart policy (OPS-06) ---
    mimir_restart_policy: unless-stopped

    # --- Resource limits ---
    # Mimir ingester is the memory hog (active series in memory).
    # 2GB fits homelab single-tenant per PITFALLS sizing.
    mimir_memory_limit: 2g

    # --- Container user (RESEARCH Finding 7) ---
    # Mimir 3.x image runs as UID 472.
    mimir_container_user: "472:472"

    # --- Network ---
    mimir_network: "{{ telemetron_network | default('telemetron') }}"

    # --- Timezone (OPS-06) ---
    mimir_tz: "{{ telemetron_tz | default('Etc/UTC') }}"
    ```

    # roles/mimir

    Deploys [Grafana Mimir](https://github.com/grafana/mimir) 3.0.6 in
    monolithic mode (`-target=all`) on a single Docker host. Mimir is
    the long-term metrics backend for Telemetron's observability plane;
    metrics land via Prometheus `remote_write` (Phase 3) and are queried
    via Grafana (Phase 5).

    Storage backend: MinIO S3 with **three distinct buckets** -- Mimir
    refuses to start with shared prefixes (Pitfall G + BACK-04).

    Mirrors the canonical role template established by `roles/minio`,
    `roles/loki`, and `roles/tempo`.

    ## What this role does

    1. Renders `/opt/telemetron/mimir/mimir.yaml` from `templates/mimir.yaml.j2`
       with MinIO S3 credentials from Ansible vault.
    2. Ensures the named Docker volume `telemetron_mimir_data` exists.
    3. Starts the `mimir` container on the `telemetron` Docker bridge
       network. Container port `9009` is NOT published to the host by
       default (`mimir_publish_host: false`).
    4. **As a blocking final task**, polls Mimir readiness via

    ## Healthcheck

    Mimir 3.0.6 is built on `gcr.io/distroless/static-debian12` -- no
    shell, no curl, no wget, and no native `-health` binary flag as of
    research (issue #9034 closed unresolved). Same approach as the Tempo
    role: a binary-alive proxy (`/bin/mimir -version`) is used as the
    Docker HEALTHCHECK to satisfy OPS-06 ("HEALTHCHECK is declared"),
    and the authoritative readiness gate is the verify task's
    in-network curl to `http://mimir:9009/ready` (returns 200 with body
    `ready` when fully started).

    future Mimir image adds one, or set `mimir_healthcheck_enabled: false`
    to skip the Docker HEALTHCHECK entirely (verify task's Ansible-side
    polling still gates readiness).
