**Bug 1 (alertmanager-verify-prom-am-probe-auto-remove-race):**
`roles/alertmanager/tasks/verify.yml` step 5 uses the documented-racy
`community.docker.docker_container` + `auto_remove: true` + `detach: false`
+ 30-iter shell-loop pattern (ansible/ansible#45272 + #47673). On fresh
deploys where the loop runs the full ~60s, Docker's reaper deletes the
container before the Ansible module can read the exit code, producing
fatal "Cannot retrieve result as auto_remove is enabled" and PLAY RECAP
failed=1.

**Bug 2 (prometheus-template-rename-bind-mount-stale-inode):**
`roles/prometheus/tasks/main.yml` and 6 sibling roles bind-mount
individual RENDERED config files (not their parent directories). Ansible
`template:`/`copy:` default `atomic_move=true` writes to .tmpXXXX and
rename(2)s into place, producing a new inode. Docker's single-file bind
pins to the original inode (kernel-fd at container start). Container
keeps reading old config until `docker restart` re-binds (moby/moby#6011,
WONTFIX since 2014).

Purpose: M1 quality bar is "boots on Rock's homelab Docker host" -- fresh
deploys must complete with `failed=0` and no manual `docker restart`
rescue. Bug 1 currently fails Test 1; Bug 2 currently fails Test 4 (which
cascades from Test 1 because the failed play never flushes handlers).
Both must be closed for Phase 4 to ship; ALERT-01 stays the only
requirement addressed.

```yaml
- name: Curl-probe Prometheus /api/v1/alertmanagers and assert AM target present (race-free via exec)
  # Bug-fix 04-02: replaces the auto_remove + while-loop pattern with
  # docker_container_exec against the running alertmanager container.
  # The AM image (quay.io/prometheus/alertmanager:v0.32.1) is busybox-based --
  # /usr/bin/wget is available (the role's own HEALTHCHECK uses it). The
  # exec API returns the exit code synchronously without container-lifecycle
  # reap, so the auto_remove race documented in ansible/ansible#45272 and
  # #47673 cannot fire. Polling via Ansible until:/retries:/delay: instead
  # of an in-container while-loop.
  community.docker.docker_container_exec:
    container: "{{ alertmanager_container_name }}"
    command: >-
      wget -qO- http://prometheus:9090/api/v1/alertmanagers
  register: am_promam_probe
  changed_when: false
  failed_when: false   # let until: own the success criteria
  retries: 30
  delay: 2
  until: >-
    am_promam_probe.stdout is defined
    and 'http://alertmanager:9093/api/v2/alerts' in am_promam_probe.stdout
  tags:
    - alertmanager
    - alertmanager-verify
```

    **8. Parent-directory bind-mount convention (Bug-fix 04-02; moby/moby#6011):**

    When bind-mounting rendered config files into a container, mount the PARENT DIRECTORY, not individual files. Ansible `template:` / `copy:` modules atomic-rename new inodes into place; Docker's single-file bind pins to the original inode at container start (kernel-fd; see moby/moby#6011, WONTFIX since 2014).
