The Phase-4 fix shape (replaces auto_remove+detach:false one-shot containers):

```yaml
- name: "<descriptive name> (in-network exec against live container)"
  community.docker.docker_container_exec:
    container: "{{ grafana_container_name }}"
    argv:
      - /bin/sh
      - -c
      - |
        set -e
        BODY=$(<curl invocation against localhost:{{ grafana_http_port }}>)
        echo "$BODY" | grep -q '<expected-payload>' || { echo "<error message>: $BODY"; exit 1; }
        echo "<success-tag>"
  register: <unique_name>
  retries: 15
  delay: 4
  until: <unique_name> is succeeded
  changed_when: false
  failed_when: <unique_name> is failed and <unique_name>.attempts | default(0) >= 15
  tags:
    - grafana
    - grafana-verify
```

Why this works:
- Runs *inside* the existing telemetron-grafana container -- curl is already
  in the grafana-oss image (`which curl` -> `/usr/bin/curl` per grafana-oss
  ship-list).
- `localhost:3000` resolves to the grafana process itself; no bridge DNS needed
  for self-probes. For datasource health, Grafana itself proxies via
  `/api/datasources/proxy/uid/{uid}/...` -- so the assertion runs against
  grafana, which then talks to prometheus/loki/tempo/mimir over the bridge.
- No auto_remove (the grafana container stays running).
- No one-shot curlimages/curl pull.
- Retries+until baked into the assertion (Phase-4 pattern -- alertmanager
  verify step 5 + 7 + 9 use this).

`grafana_admin_user` and `grafana_admin_password` interpolate at template time
(Ansible-side), so the `-u admin:$PASS` form embeds the password into the argv
shell command. This matches how the current implementation does it.

Step 1 (HEALTHCHECK poll) is UNCHANGED -- it uses `docker_container_info`,
not `docker_container`, and has never been affected.

Step 10 (Gate 9.5) is UNCHANGED -- it uses `ansible.builtin.shell` on the host,
not `docker_container`. It executes after the eight rewritten probes and
asserts gate_9_5_ok against /opt/telemetron/grafana/provisioning/dashboards/telemetron/.
