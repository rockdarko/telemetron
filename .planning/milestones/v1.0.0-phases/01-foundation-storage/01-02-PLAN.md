    ```yaml
    ---
    # Telemetron — M1 deploy orchestrator (Docker target)
    #
    # Brings up the Telemetron observability plane on a single Docker host.
    # Phase 1 ships the foundation: the `telemetron` Docker bridge network
    # (created in pre_tasks below) plus the MinIO role with its bucket-bootstrap
    # gate. Phases 2-6 add the rest of the 14 roles.
    #
    # Per-role targeted re-runs use --tags <role>:
    #   ansible-playbook -i inventory/example-homelab playbooks/deploy_docker.yml --tags minio
    #
    # Usage:
    #   ansible-playbook -i inventory/example-homelab \
    #                    playbooks/deploy_docker.yml \
    #                    --ask-vault-pass

    - name: Telemetron — deploy to Docker host
      hosts: telemetron
      gather_facts: true
      become: false

      collections:
        - community.docker

      pre_tasks:
        - name: Ensure the telemetron Docker bridge network exists
          community.docker.docker_network:
            name: "{{ telemetron_network }}"
            driver: bridge
            state: present
          tags:
            - always
            - network

      roles: []
      # Phase 1 plan 03 wires in the minio role here:
      #   - role: minio
      #     tags: [minio]
      #
      # Subsequent phase plans extend this list in dependency order:
      #   Phase 2: loki, tempo, mimir
      #   Phase 3: prometheus, opentelemetry, fluentbit, node_exporter
      #   Phase 4: alertmanager, hook_router
      #   Phase 5: grafana, karma, promlens
      #   Phase 6: nfsd (opt-in via enable_nfsd flag)
    ```

    **Notes for the executor:**
    - `become: false` is the default because Docker socket access via the current user is the homelab norm; roles can elevate per-task if they need root for a specific file write under `/opt/telemetron/`.
    - The `community.docker` collection is named in `collections:` — this requires the collection to be installed on the control host (`ansible-galaxy collection install community.docker`). Document the prerequisite in the inventory README (already done in Task 1's README).
    - The `roles: []` block is intentionally empty in Plan 02; Plan 03 Task 3 will replace it with `roles: [ { role: minio, tags: [minio] } ]`.
    - The pre_task has tags `always` (runs even with `--tags <role>` because every role needs the network) and `network` (so operators can run `--tags network` for just the network creation if they want).
    - The pre_task is idempotent: `community.docker.docker_network` with `state: present` reports `changed=false` if the network already exists with the same driver. Per D-19, we avoid `state: restarted` semantics anywhere.
